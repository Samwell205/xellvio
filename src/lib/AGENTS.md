# src/lib rules
- Owner email designs are static React trees with hosted artwork; recipient values are escaped and links scheme-checked, generic notices retain event-owned text, and previews share send rendering without changing triggers/providers.
- Lifecycle first-send targeting uses immutable campaign first_launched_at, count, tracking start and a short relevance window for both email and dashboard; historical discovery never congratulates longstanding businesses.
- Support creation serializes per business and appends to the unresolved conversation; explicit merges retain audit histories and notify the requester, with service-only SQL validation.
- Optional lifecycle promotional/re-engagement emails require the existing external sender and never enter built-in app-email queues; template replacement remains owner-controlled.
- Verifier registration validates through verifier-registration.ts before provisioning/submission and checks single-number child-account ownership; only carrier-confirmed identifiers can mark submitted.
- Finance page views reuse timestamped saved reports until explicit recalculation; Billing shares financeTenantReport but reads current wallets separately. Optional margin/pricing/recovery views load only when opened, and carrier reads never delay Finance.
- Admin SMS balance uses twilio-account-balance.server.ts with the funded parent credentials and saved twilio alert settings; failed reads are not confirmed zero balances. Number sub-account sending remains separate and guarded.
- Receipt recovery is lookup-only, bounded to six workers with stable ID cursors; accept exact matching final receipts, try the other server-owned connection only on 404, and keep unconfirmed distinct from failure. Never resend or change balances during recovery.
- Line-type screening (line-type.server.ts) is free and offline (libphonenumber numbering-plan data): never call paid carrier lookups or debit accounts for it; only definite landline/toll-free patterns block, ambiguous numbers stay unknown and sendable. Upload auto-check runs only when accounts.auto_screen_uploads is on, screening just the uploaded phones in client-driven chunks.
- Screening rejects keyword/AI review flags; when AI review is unavailable (e.g. no AI credits) the fallback in ai-unavailable-fallback.ts decides — rule hits are blocked with the reason shown, everything else sends without admin approval, so AI outages never stop tenants; shared keyword rules stabilize recurring risky demands. No timed approval; hard categories suspend; sendMessage rechecks keywords before each carrier call. Carrier spam refusals (40002): campaigns created after the rollout cutoff with no previous attempts enroll in passive monitoring (campaign_spam_* tables, service-role-only SQL). Owner correction 2026-10-22: no initial-25/250-outstanding limits, no feedback-timeout pause — missing carrier results must not hold dispatch; keep existing throughput, concurrency, pacing and rate-limit handling. Signed final receipts pause remaining sends + notify the tenant once when >=20 distinct finalized results contain >=20% spam refusals. Paid claims go through spam_gate_claim only (live campaign/account checks, unchanged billing). No per-message monitoring RPCs or full-campaign receipt scans in dispatch. Confirmed carrier pauses never auto-resume on account-hold lift; legacy feedback-timeout pauses need a deliberate screened resume. See db-proposals/20261022-remove-carrier-feedback-delays.sql and carrier-pause-policy.test.ts.
- Dedicated-line (SM…) receipt recovery lives in twilio-receipt-recovery.server.ts: lookup-only via the owning subaccount, replayed through handleStatus; a 5-minute sweep-receipts cron rotates a saved cursor over every open message and relabels texts the network still shows only "sent" after 24h as delivery_unconfirmed (no network report), so they never show awaiting forever. Never resends or charges.

- Dispatch holds all sending (recipients stay queued, never failed) when the funded carrier balance is at/below the buffer or a recent send hit 30002/20003, via carrier-funds-guard.ts; protects carrier health score.
- Actual Twilio price per message comes from twilio-price-sync.server.ts (lookup-only, run inside the reconcile cron slice); report it beside the country_rates estimate, never replace tenant charges with it.
- Individual destination/sender rejections never infer regional blocks: dispatch ignores legacy global geo blocks because one request cannot prove another account's permissions.
- Campaign accounting uses recorded tenant debits independently of delivery status; carrier recovery is lookup-only, campaign/SID-matched, USD-only and service-scoped. Message prices exclude reconciled surcharges, so confirmed profit stays unavailable.
- Screen personalized recipients during planning before paid claims; preserve the send-time safety backstop and never automatically refund historical charges.
- Tenant campaign "Charged/Spend" totals come from campaign-charges.ts (wallet debits minus refunds) so campaign screens always match the balance change.
- Campaign planning rows are built in campaign-plan-rows.ts so queued and skipped recipients expose the same columns; a column missing from one row in a bulk upsert is written as NULL and rejects the whole batch, stopping the campaign.
